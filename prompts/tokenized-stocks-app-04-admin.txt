## Token and market rules

### 1) Cash token = USDT (must be first)

- Before any stock market, ensure a **USDT** cash token exists.
- If none is recorded yet on a fresh venue, create it first with `ActionBuilder::create_token`:
  - name `USDT`, symbol `USDT`, mintable `true`
  - `to` = admin/validator address (supply goes to admin)
- Persist `CASH_TOKEN_ADDRESS` / USDT `ContractAddress` (often `0x02…` on a fresh chain). Do not hard-code if the receipt printed a different address — parse from receipt events (SDK helpers like `extract_token_address_from_events` if available).

### 2) Create a stock market (e.g. AAPL)

One Admin action “create AAPL market” (or form: symbol `AAPL`, name `Apple`) must do **both**:

1. `create_token` for the stock (e.g. name Apple, symbol AAPL, mintable, `to` = admin)
2. `create_market` / spot market for **`AAPL/USDT`**:
   - `base_token` = AAPL
   - `quote_token` = USDT (cash from step 1)
   - `creator` = admin address
   - **Tick size must align with Hyperliquid US equity L2** (coins `xyz:AAPL`, `xyz:TSLA`, `xyz:INTC`, etc.):
     - HL equity books quote in **dollar and cents** (prices like `330.41`, `330.40` — typically **$0.01** steps in the top of book).
     - LightPool `tick_size` is on-chain raw units: **`0.01 * TOKEN_SCALE` = `10_000`** (not `1_000_000` / $1).
     - **Do not** use a $1 tick. Chapter 6 `equity-liquidity-maker` mirrors HL depth (e.g. 10 levels) onto LightPool by aligning prices to this tick; a $1 tick collapses HL’s sub-dollar depth-10 into 1–2 LP levels, so the LightPool book will look empty/shallow even when the bot is healthy.
     - Apply the same tick for **AAPL, TSLA, INTC** and any other US equity symbol created in Admin.
   - `min_order_size`: sensible default (e.g. `0.1 * TOKEN_SCALE` = `100_000`), not coarser than needed for demo sizes.

Parse and store:

- base `ContractAddress`
- quote `ContractAddress` (USDT)
- spot market `ContractAddress` (typically `0x03…`)
- display name `AAPL/USDT`

If USDT is missing, create USDT first, then AAPL + market — do not create AAPL/USDT with a missing quote.

## Backend API (suggested)

Keep thin Axum backend as clob-index client + admin signer. Example routes (names can vary, behavior must match):

| Method | Path | Behavior |
|--------|------|----------|
| GET | `/api/cash` | Current USDT `ContractAddress` or null |
| POST | `/api/admin/ensure-cash` | Create USDT if missing; return address |
| POST | `/api/admin/markets` | Body: `{ "symbol": "AAPL", "name": "Apple", ... }` → ensure USDT, create stock token, create `SYMBOL/USDT` spot market; return stored market |
| GET | `/api/markets` | List markets the app has created/registered (symbol, name, base, quote, spot_market) |
| GET | `/api/markets/:id` or by symbol | One market |

Persist markets in `$LABS/data/tokenized-stocks/registry.json` (clob-index `GET /api/markets` is event-oriented — **do not rely on it** for spot pair list). After create, append to that registry. Do **not** write durable course data under the app source tree.

Submit path: always sign with admin key → `POST {CLOB_INDEX_URL}/api/tx/submit`.

## Frontend

### Admin (`/admin`)

Replace placeholders with working forms:

1. **Cash / USDT** — show current cash token address; button “Ensure USDT” / create cash if missing.
2. **Create stock market** — inputs for symbol (default `AAPL`) and name (default `Apple`); submit creates **token + `SYMBOL/USDT` market** in one flow; show resulting addresses.
3. Show last errors from submit/receipt clearly.

### Markets list (trade page)

- Load `GET /api/markets` (app backend).
- Display real pairs (e.g. `AAPL/USDT`).
- On select, store selected spot `ContractAddress` (and base/quote) in app state for later chapters (chart / book / ticket).
- If empty, show empty state pointing user to Admin.

Do **not** implement chart bars, live order book, place-order ticket, deposit/withdraw bridge, or liquidity bot in this step.

## Types

- `Address` = user/admin (20-byte), e.g. validator `0xf39F…`
- `ContractAddress` = token / spot market (8-byte module prefix, `0x02…` / `0x03…`)
- Never mix them.
