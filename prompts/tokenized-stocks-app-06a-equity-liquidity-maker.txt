## Goal

In **`lightpool-bot`** (not `tokenized-stocks-app`):

1. Add a **new** strategy module and binary named **`equity-liquidity-maker`**.
2. CLI takes LightPool equity **symbol(s) only** for the HL side, e.g. `--symbol AAPL,TSLA,INTC`. For each symbol `S`, the bot **internally** sets Hyperliquid coin = `"xyz:" + S` (e.g. `xyz:AAPL`, `xyz:TSLA`, `xyz:INTC`). **No** CLI flag for Hyperliquid coin / mapping.
3. Subscribe to Hyperliquid order book (snapshot + deltas) for that coin.
4. Reconcile and place/cancel orders on the matching LightPool **spot** market so clob-index shows bids/asks.

Do **not** change the existing `liquidity-maker` Polymarket path except to leave it working.

## Behavior

```text
--symbol AAPL,TSLA,INTC
    → for each S in [AAPL, TSLA, INTC]:
         hl_coin = "xyz:S"
         → subscribe Hyperliquid L2 (book + deltas)
         → maintain local HL book cache
         → reconcile vs bot-owned orders on LightPool spot for S
         → place / cancel on LightPool via execution client → clob-index
```

Use the same high-level pattern as `LiquidityMaker` + `sync.rs`:

1. Data actor / strategy receives HL book updates.
2. Batch deltas, then reconcile target depth onto LightPool.
3. Buy locks quote (USDT); sell locks base (stock token) — respect LightPool spot rules.
4. Do not mirror a Hyperliquid level whose size is below **0.1 share**. LightPool spot `min_order_size` is raw `100_000` (`TOKEN_SCALE` `1_000_000`). Drop those levels from the reference book. Do not place or modify a LightPool order under 0.1. If the only reason a resting LightPool order remains is that the HL size fell below 0.1, cancel it.
5. Maker inventory: Admin/maker wallet should already hold USDT and base (fund in Admin if needed); document that in the binary `--help` / short module docs.
6. Do not self-trade in one reconcile. `without_crossing_places` drops a new place that would hit a still-open opposite order, or that would cross another new place in the same batch. Cancels and modifies still go out. When a new bid and a new ask cross, keep the bid and defer the ask. Log `Defer … crossing place(s) so this batch cannot trade with itself`.
7. On `OrderCanceled`, call `reconcile_after_own_cancel` and run the existing `reconcile_pair` against the Hyperliquid book already in cache. If any order for that instrument is still `PendingCancel` (`orders_inflight` is not empty), return. After the last cancel is confirmed and inflight is empty, place the levels deferred in rule 6. Do not wait for the next Hyperliquid book delta.
8. Rest 20 levels per side (`--depth` default 20), not 10. Hyperliquid's 20 bids and 20 asks are placed on the LightPool spot. The UI still shows only the top 10.

Wire LiveNode with:

- Hyperliquid **data** client (for `xyz:SYMBOL`)
- LightPool **data** + **execution** clients (clob-index), private key = Anvil #0 / env
