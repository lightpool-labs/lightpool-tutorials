## Layout rules

### Order ticket column

1. **Market / Limit tabs** at the top of the order form (above Buy / Sell).
2. **Buy / Sell** side toggle under those tabs.
3. **Available balance** is the first line under Buy / Sell (relevant Available for the selected side and market: quote for buy, base for sell). Use the connected wallet balances already loaded in chapter 7.
4. **Size** input next. Add a **draggable percentage scale** (slider) so the user can set size as a percentage of that available balance.
   - **Buy** size is base amount = (available quote × pct / 100) / price. **Sell** size is base amount = available base × pct / 100 (no price needed).
   - **If there is no usable price** (empty Limit price field, or Market): use mid = `(best bid + best ask) / 2` from the selected market’s LightPool order book (clob-index snapshot / live book). If only one side exists, use that side; else fall back to `last_trade_price` when present.
   - **Book price units:** clob-index book `price` strings are in **cents**. Convert to human USDT dollars with `price / 100` before using mid (or any book level) in the size formula — same display rule as the chapter 6b order book UI. Do **not** treat raw book prices as dollars (that understates size by ~100×).
5. For **Limit**, show a price field. For **Market**, hide or disable price.
6. Put the primary action button (**Enable** / submit placeholder) at the **bottom** of the order form, above the Deposit / Withdraw divider. Keep it disabled in this step (no place-order).
7. **Deposit** and **Withdraw** stay below that divider. Clicking either opens a **dialog** to choose the token and enter the amount, then run the existing chapter 7 MetaMask flow for that token. Do not keep the inline amount field as the only way to enter amount.

### Shared divider

Draw a horizontal line above the Deposit / Withdraw section in the order-ticket column. That line must **align with** and **visually continue into** the horizontal line above the Balances area in the bottom user-state block (one continuous divider across the ticket column and the bottom tabs column). Adjust CSS grid / borders so the two lines meet; do not leave a gap or a misaligned step.

### User-state tabs (`BottomTabs`)

Tab order and names:

| Tab | Meaning | Columns (headers only in this step) |
|-----|---------|-------------------------------------|
| **Balances** | Asset balances | Asset, Available, Locked, Total |
| **Open orders** | Orders still live on the book | Market, Side, Price, Size, Status |
| **Order history** | Past orders (filled, cancelled, rejected) — rename from `History` | Time, Market, Side, Price, Size, Status |
| **Trade history** | Executions / fills — rename from `Fills` | Time, Market, Side, Price, Size, Fee |

Rules:

- **Balances:** show only assets whose Available, Locked, or Total is **not** all zero. Hide rows where Available, Locked, and Total are all `0`.
- **Open orders**, **Order history**, and **Trade history:** keep empty placeholder tables with the column headers above. Do not wire live data yet.
- **Order history** = one row per order lifecycle (not per fill). **Trade history** = one row per execution/fill (one order may produce many fills).
